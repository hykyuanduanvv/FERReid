# 运行计划（2026-10-01）：强基线 + Protocol-2

本文件说明 2026-10-01 版本新增实验的**目的、命令、预计时间与判读方式**。代码基于 2026-09-30 服务器 `/root/FERReID`（DINOv2、VPT、分析脚本）整理，并加入本轮新功能。9/30 的结果与报告见 [results/archive_20260930](../results/archive_20260930/REPORT_2026-09-30.md)。

## 1. 为什么做这些实验

9/30 的结论：DINOv2 远好于 ViT-B/16；固定可学习 prompt（VPT）≥ VICP，即 LLM + 上下文对性能没有可测贡献；域专属 prompt 上限大；在"真正使用标注"的生成器上，选哪 k 个人确有影响。

本轮目标：
1. **强基线**：审稿人会要求与"按标准做法训练的强基线"比较。沿用 VICP 默认的只有 triplet、LoRA 只在最后 4 层、没收敛等设置可能明显偏弱。本轮加入 BNNeck + ID 交叉熵、训练到收敛、行人采样等，并加入**全参数微调 DINOv2** 基线。
2. **Protocol-2**：Market1501 / MSMT17 / CUHK-SYSU / CUHK03 留一交叉，测试集身份数远多于 VIPeR/GRID/i-LIDS。
3. **严格 label-free 的选择设定**：选择方法只看无标签图像，不再借用 pid 分组（见 §4）。

## 4. label-free 选择（本轮修正的缺陷）

旧实现（`identity`）：候选池先按真实 pid 分组，选择方法直接挑"人"，并只在"出现于 ≥2 个摄像头"的人中挑——选之前就用了标签。

新实现（`image`，默认）：
- 选择方法只能看到候选池的**图像路径与摄像头 ID**（监控数据自带，不需标注），返回 k 张**锚点图**；
- 模拟标注：对每张锚点图，标注者找出**同一人在另一摄像头下的一张图**（`NO_CAMERA_DOMAINS` 中的 i-LIDS、CUHK-SYSU 没有真实摄像头，则找同一人的另一张图）；
- 锚点所属的人没有合格配对（`n_fail`），或与之前的锚点是同一人（`n_dup`），**照样消耗预算**；结果 CSV 记录 `n_pairs / n_fail / n_dup`；
- 选择器接口 `fn(pool: ImagePool, k, rng)` 拿不到 pid（标签保存在私有的 annotation oracle 中）。

历史结果用 `identity` 得到。复现旧结果时须显式传 `--selection_unit identity`（`scripts/run_*.sh` 已加）。`tests/test_selection.py` 验证了 `identity` 与旧代码逐项一致。

随机选图 k=16 时的平均配对数（50 个种子）：VIPeR 15.8、GRID 15.6、Market 15.9、CUHK03 15.9、i-LIDS 14.2（i-LIDS 平均 1.8 张锚点重复选中同一人）——这类浪费正是选择方法应当避免的。

所有阶段通过多卡启动器运行：一张卡一个任务，自动排队，日志在 `experiments/_launch/<任务名>.log`，成功的任务再次运行时自动跳过（可断点续跑）。


时间估计依据 9/30 在 RTX 4090 D 上的实测：DINOv2 VPT 3000 步 ≈ 19 分钟，VICP ≈ 39 分钟，plain ≈ 12 分钟；全参微调、12000 步和大目标域评测为推算，首次运行请以日志为准。

## 6. 判读与注意事项

- `pick_best.py` 的分数是最后 3 次验证 mAP 的平均。9/30 同配置换种子在验证集上相差 0.4–0.8 mAP，所以 < 1 mAP 的差别不作结论。
- 阶段 3 各选项是**单独**有效，`final.sh` 中的组合本身未经验证；如组合后阶段 4 变差，请回退。
- **强基线的判据**：全参微调 DINOv2（`s1_plain_full`、`s2_plain_full_long`、`s4_full_*`）若明显强于 LoRA 版本，后续方法应叠加在全参 backbone 之上，并在论文中以它为主要对照。
- 阶段 4 目标域评测中，VPT / plain 不使用上下文（结果与 k 无关）；VICP 报告 k=4、16 × 3 个上下文种子。
- 分析脚本（`context_sensitivity.py`、`oracle_prompt.py`、`prompt_select.py`、`label_value.py`）把整个 split 的图像缓存在 GPU 上，只适用于 VIPeR/GRID/i-LIDS 这类小目标域；在 Protocol-2 大目标域上需要改为流式读取（未实现）。

## 8. 方向 A：让 prompt 真正依赖上下文（`plans/dirA.tasks`）

**问题**（9/30 实验）：VICP 的 LLM 读懂了上下文（答题准、隐状态随上下文变化），但生成的 prompt 几乎是常量（余弦 ≈ 0.99），固定 prompt 的 VPT 不比它差。而用目标域标签直接调 prompt，上限可 +4 ~ +11 mAP（DINOv2）、且是域专属的。方向 A 要让"读 k 对标注图 → 生成域专属 prompt"在**不更新参数**的前提下起作用，这是方向 B（选哪 k 个人）在 in-context 设定下成立的前提。LLM 保持冻结，改动全在 CV 侧。

**改动**（默认全关；`--model_type vicp` 下组合使用）：

| 选项 | 作用 | 针对的原因 |
|---|---|---|
| `--prompt_mode residual` | prompt = 可学习基础 prompt（等价 VPT，零初始化）+ 每层门控 × `prompt_mlp(LayerNorm(h))`；`prompt_mlp` 改为小随机初始化 | 原零初始化线性层把随上下文变化的部分压掉约 2/3；上下文无用时模型退化为 VPT，不会比 VPT 差 |
| `--ctx_center ema` | `h` 先减去其滑动均值，修正量只能来自"随上下文变化的部分" | 常数 prompt 的捷径 |
| `--episode_context_ids 16 --episode_context_ids_min 4` | 训练时 batch 前 N 个身份（N ∈ [4,16] 随机）只作上下文，检索损失只在其余身份上计算 | 原训练中上下文 = 被检索的图，模型不读上下文也能学好 |
| `--pseudo_domains camera_pair` | 伪域 = (数据集, 摄像头对)；batch 来自同一摄像头对，每人图像在两摄像头间交替 | 只有 2 个源域学不出"不同域用不同 prompt"；调参折上得到 **62 个伪域**（Market 15、MSMT17 47，≥64 人），覆盖 1,771 / 1,792 人 |

`plans/dirA.tasks`：a0（原 VICP）、a1（残差）、a2（残差 + EMA）、a3（原 VICP + episode）、a4（残差 + EMA + episode）、a5（全部）、a6（残差 + EMA + 摄像头对伪域），各 3,000 步；随后 `scripts/context_gain.py` 在 VIPeR/GRID/i-LIDS（3 个划分）上比较。7 个训练约 40 分钟/个（4 卡约 1.5 小时）+ 7 个评测约 10 分钟/个。依赖阶段 1 的损失选择（`plans/chosen.sh`），参照模型为阶段 1 的 VPT（同数据、同损失）。

```bash
python scripts/launch_tasks.py plans/stage1_loss.tasks --gpus 0,1,2,3 && python scripts/pick_best.py stage1
python scripts/launch_tasks.py plans/dirA.tasks --gpus 0,1,2,3
cat experiments/g_a*/summary.json     # 或看各 gain.log 末尾的表
```

**判据**（事先确定）：在未见目标域上，`own`（本域上下文 k=16 的 prompt）相对 `base`（同一模型的无上下文 prompt）与 `reference`（阶段 1 VPT）**都高 ≥ ~1 mAP**，且相对 `cross`（其他域上下文）**也高**（`specificity` > 0），同时 `cos_own_own` 明显低于 0.99（prompt 确实在动）。三个域中多数满足才算方向 A 成立；否则在当前 VICP 框架下放弃方向 A，B 改用"k 个标注人调 prompt"作载体。

**限制**：判定在 VIPeR/GRID/i-LIDS 小目标域上进行（这些域已被多次使用，仅作方向判断，不作最终结果）；`context_gain.py` 把图像缓存在 GPU 上，不适用于 Protocol-2 大目标域。

## 9. 方向 B：label-free 的上下文选择（`plans/select_test.tasks`、`plans/select_train.tasks`）

**问题**：预算 k 张锚点图时，挑哪些图去标注，生成的 prompt 最好。选择算法只看无标签信息：图像、摄像头 ID、无标签特征。选择发生在测试时，**换选择算法不需要重新训练模型**；只有阶段二（训练时也用选择算法）需要为每个算法训练一次。

**设计思路**：上下文要提供 ① 域的整体外观、② 跨摄像头该忽略的变化（正样本对）、③ 外观相近时该关注的差异（难负样本对），并且 ④ 不浪费预算。少样本主动学习的经验是：预算极小时"典型 / 有代表性"往往比"多样"或"难"更重要，需要实测。

| 类别 | 选择器 | 做法 |
|---|---|---|
| 参照 | `random`、`first` | 随机；列表前 k 张 |
| 效率 | `dedup` | 随机顺序，跳过与已选图过于相似（可能同一人）的图 |
| | `pairable` | 优先在其他摄像头有高置信匹配的图（减少标注失败），去重 |
| 代表性 | `typical` | k-means 成 k 簇，每簇取最典型（邻域最密）的图（TypiClust 式） |
| 覆盖 | `kcenter` | 特征空间最远点采样 |
| | `camera_balanced` | 锚点在各摄像头间轮流分配，去重（无摄像头的域退化为 dedup） |
| | `style_cover` | 浅层 patch token 的通道均值/方差聚成 k 簇，每簇取最靠近中心的图 |
| 信息量 | `hard_negative` | 成对选外观相近、但相似度低于"同一人"阈值的图，构成难负样本 |
| 组合（候选方法） | `facility`、`facility_camera` | 贪心最大化 facility location（代表性 + 覆盖，单调子模，贪心有 1−1/e 近似保证），`facility_camera` 另加未覆盖摄像头奖励；均带去重约束 |

**特征**：模型自身训练过的编码器（不加 prompt）——对目标域仍是无标签的，而且人物相似度远好于未训练的预训练主干（实测：用预训练特征时 GRID 上 `facility` / `typical` 会重复选同一个人）。可选 `source="pretrained"`。另用"跨摄像头互为最近邻"判定同一人，用于去重。"同一人"阈值取随机图像对相似度的 99 分位数（随机对几乎都是不同的人）。每个 split 只提取一次。

**阶段一：测试时比较**（`plans/select_test.tasks`，需要阶段 1 和方向 A 的模型）

| 任务 | 生成器 | 设置 | 时间（单卡） |
|---|---|---|---|
| `sel_tuned_{viper,grid,ilids}` | VPT + 用 k 对标注图调 prompt（lr 3e-4，300 步；已知对选人敏感） | 3 个 split，k = 4、16，每个选择器 3 次，random 10 次 | 每个约 2–3 小时 |
| `sel_ic_vicp` | 原 VICP\*（对照：预期对选择不敏感） | 3 个 split，k = 4、8、16，5 次，random 10 次 | 约 1–1.5 小时 |
| `sel_ic_abest` | 最好的方向 A 模型（`A_BEST_RUN`，默认 a5_all） | 同上 | 约 1–1.5 小时 |

输出（`experiments/sel_*/`）：`summary.csv`——每个选择器的平均、标准差、最差、相对 random 的提升、离 random oracle@10 的差距、平均有效配对数；`correlation.csv`——在随机选择中，选择性质（覆盖摄像头数、多样性、典型性、可配对性、风格离散度、有效配对数）与 mAP 的秩相关（已去除 split / k 的影响），回答"好的上下文好在哪"。

**阶段二：训练时也用选择算法**（`plans/select_train.tasks`）：以最好的方向 A 设置（`A_BEST_ARGS`，含 episode 划分）为基础，加 `--train_context_selector <选择器>`，由选择器从每个 batch 中挑出上下文身份（用 batch 内的无标签特征；batch 中没有摄像头 ID，摄像头类选择器退化为无摄像头版本，`style_cover` 不支持）。默认列了 `typical`、`facility`、`kcenter`，**阶段一结束后请改成表现最好的 1–3 个**。每个约 40 分钟训练 + 1 小时评测；对照是 `sel_ic_abest`（同设置、随机上下文训练）。

**判读**：阶段一看"相对 random 的平均提升"和"最差情况的改善"，以 random 的标准差与 9/30 噪声对照（同一组人只换种子：0.4–0.8 mAP）为尺度；阶段二看"训练 + 测试都用选择器"相对"只在测试时用"的额外提升。Protocol-2 大目标域上，可用 `eval_context.py --methods <选择器列表>` 评测 in-context 生成器（自动提取候选池特征）；调 prompt 生成器与 `eval_selectors.py` 只适用于小目标域。
