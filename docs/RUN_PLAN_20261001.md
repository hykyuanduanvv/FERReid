# 运行计划（2026-10-01）：强基线 + Protocol-2

本文件说明 2026-10-01 版本新增实验的**目的、命令、预计时间与判读方式**。代码基于 2026-09-30 服务器 `/root/FERReID`（DINOv2、VPT、分析脚本）整理，并加入本轮新功能。9/30 的结果与报告见 [results/archive_20260930](../results/archive_20260930/REPORT_2026-09-30.md)。

## 1. 为什么做这些实验

9/30 的结论：DINOv2 远好于 ViT-B/16；固定可学习 prompt（VPT）≥ VICP，即 LLM + 上下文对性能没有可测贡献；域专属 prompt 上限大；在"真正使用标注"的生成器上，选哪 k 个人确有影响。

本轮目标：
1. **强基线**：审稿人会要求与"按标准做法训练的强基线"比较。沿用 VICP 默认的只有 triplet、LoRA 只在最后 4 层、没收敛等设置可能明显偏弱。本轮加入 BNNeck + ID 交叉熵、训练到收敛、行人采样等，并加入**全参数微调 DINOv2** 基线。
2. **Protocol-2**：Market1501 / MSMT17 / CUHK-SYSU / CUHK03 留一交叉，测试集身份数远多于 VIPeR/GRID/i-LIDS。
3. **严格 label-free 的选择设定**：选择方法只看无标签图像，不再借用 pid 分组（见 §4）。

## 4. label-free 选择（本轮修正的缺陷）

旧实现（`identity`）：候选池先按真实 pid 分组，选择方法直接挑"人"，并只在"出现于 ≥2 个摄像头"的人中挑——选之前就用了标签。

新实现（`image`，默认）：
- 选择方法只能看到候选池的**图像路径与摄像头 ID**（监控数据自带，不需标注），返回 k 张**锚点图**；
- 模拟标注：对每张锚点图，标注者找出**同一人在另一摄像头下的一张图**（`NO_CAMERA_DOMAINS` 中的 i-LIDS、CUHK-SYSU 没有真实摄像头，则找同一人的另一张图）；
- 锚点所属的人没有合格配对（`n_fail`），或与之前的锚点是同一人（`n_dup`），**照样消耗预算**；结果 CSV 记录 `n_pairs / n_fail / n_dup`；
- 选择器接口 `fn(pool: ImagePool, k, rng)` 拿不到 pid（标签保存在私有的 annotation oracle 中）。

历史结果用 `identity` 得到。复现旧结果时须显式传 `--selection_unit identity`（`scripts/run_*.sh` 已加）。`tests/test_selection.py` 验证了 `identity` 与旧代码逐项一致。

随机选图 k=16 时的平均配对数（50 个种子）：VIPeR 15.8、GRID 15.6、Market 15.9、CUHK03 15.9、i-LIDS 14.2（i-LIDS 平均 1.8 张锚点重复选中同一人）——这类浪费正是选择方法应当避免的。

## 5. 实验阶段

所有阶段通过多卡启动器运行：一张卡一个任务，自动排队，日志在 `experiments/_launch/<任务名>.log`，成功的任务再次运行时自动跳过（可断点续跑）。

```bash
python scripts/launch_tasks.py plans/stage1_loss.tasks --gpus 0,1,2,3        # 先 --dry-run 查看命令
```

超参数一律在 **调参折** 上选：Protocol-2 中"目标 = CUHK-SYSU"那一折的源域是 Market、MSMT17、CUHK03；调参时再留一个源域做验证——用 Market + MSMT17 的 train 部分训练、CUHK03 验证（未见过的域）。**全程不看任何目标域**，阶段 1–3 也**不需要 CUHK-SYSU**。

| 阶段 | 任务文件 | 内容 | 任务数 | 单任务时间（24GB 卡） | 4 卡墙钟 |
|---|---|---|---|---|---|
| 1 损失与全参基线 | `stage1_loss.tasks` | VPT：triplet vs +BNNeck/CE；plain+BNNeck/CE（LoRA / 全参） | 4 | 20–40 分钟 | ~40 分钟 |
| → | `python scripts/pick_best.py stage1` | 写 `plans/chosen.sh`（LOSS_ARGS） | | | |
| 2 收敛 | `stage2_converge.tasks` | 选定损失的 VPT、全参基线各 12000 步，cosine + warmup | 2 | 1.5–2.5 小时 | ~2.5 小时 |
| 3 行人调参 | `stage3_sweep.tasks` | 每次只改一项：PK/跨摄像头采样、混合 batch、LoRA 层数与秩、prompt 数、学习率与调度、去 WPA、margin | 12 | ~20 分钟 | ~1 小时 |
| → | `python scripts/pick_best.py stage2` / `stage3` | 收敛报告；把相对参照提升 ≥ +1.0 mAP 的选项写入 `plans/final.sh`（**请人工检查**） | | | |
| 4 Protocol-2 | `stage4_protocol2.tasks` | 4 个目标 × {VPT, VICP, 全参基线} 训练 + 目标域评测（需 CUHK-SYSU） | 12 + 12 | 训练 1.5–3 小时；评测 5–40 分钟 | ~9 小时 |

阶段 2 与 3 互不依赖，可以合并跑：`python scripts/launch_tasks.py plans/stage2_converge.tasks plans/stage3_sweep.tasks --gpus 0,1,2,3 --merge`。

**总计（4 卡）**：约 13 小时墙钟；8 卡约 8 小时（阶段 4 训练时长决定下限）。单卡约 40 小时。

时间估计依据 9/30 在 RTX 4090 D 上的实测：DINOv2 VPT 3000 步 ≈ 19 分钟，VICP ≈ 39 分钟，plain ≈ 12 分钟；全参微调、12000 步和大目标域评测为推算，首次运行请以日志为准。

## 6. 判读与注意事项

- `pick_best.py` 的分数是最后 3 次验证 mAP 的平均。9/30 同配置换种子在验证集上相差 0.4–0.8 mAP，所以 < 1 mAP 的差别不作结论。
- 阶段 3 各选项是**单独**有效，`final.sh` 中的组合本身未经验证；如组合后阶段 4 变差，请回退。
- **强基线的判据**：全参微调 DINOv2（`s1_plain_full`、`s2_plain_full_long`、`s4_full_*`）若明显强于 LoRA 版本，后续方法应叠加在全参 backbone 之上，并在论文中以它为主要对照。
- 阶段 4 目标域评测中，VPT / plain 不使用上下文（结果与 k 无关）；VICP 报告 k=4、16 × 3 个上下文种子。
- 分析脚本（`context_sensitivity.py`、`oracle_prompt.py`、`prompt_select.py`、`label_value.py`）把整个 split 的图像缓存在 GPU 上，只适用于 VIPeR/GRID/i-LIDS 这类小目标域；在 Protocol-2 大目标域上需要改为流式读取（未实现）。
